# Renovate Operations (renovate-ops)

This skill provides procedures and verification tools for maintaining the automated dependency update pipeline managed by Renovate across the dotfiles repository.

## Architecture

* **Source of Truth**: [renovate.yml](file:///renovate.yml)
* **Compiled Configuration**: [renovate.json](file:///renovate.json) (generated from `renovate.yml` via `yq`)
* **Tracked Package Domains**:
  * Root environment tools: `.env` (`RNV_VERSION`, `SEMV_VERSION`, `MISE_VERSION`, `IP2BIN_VERSION`, `UV_VERSION`, `PY_VERSION`)
  * Task runners: `xc`, `bin/install-via-git-go.sh`
  * Language requirements: `requirements/{cargo,go,python,node,gem}`
  * Git sub-builds: `ivg/renovate.lock` (generated by `rnv`)
  * Emacs treesit grammars: `.emacs.d/treesit-language-source-alist.el`

## Operations & Runbooks

### 1. Synchronize & Validate Configurations

Whenever `renovate.yml` is edited, compile it to `renovate.json` and verify regex matchers against tracked target files:

```bash
bash .agents/skills/renovate-ops/scripts/renovate-sync.sh
```

This helper script:
1. Compiles `renovate.yml` to `renovate.json` using `yq`.
2. Validates that every declared `customManager` regex pattern matches at least one entry in its corresponding target file.
3. If Docker is available, runs the official `renovate-config-validator --strict`.

### 2. Manual Compilation

If modifying `renovate.yml` manually, re-generate `renovate.json`:

```bash
yq -o json renovate.yml > renovate.json
```

Or run via the task runner:

```bash
./xc renovate.json
```

### 3. Dry-Run Execution

To simulate Renovate package extraction and PR generation against the repository:

```bash
# Requires GitHub Personal Access Token in $TOKEN
TOKEN="ghp_xxx" bin/renovate-dry.sh
```

Or invoke the shell alias if sourced in zsh:

```bash
renovate-dry
```

### 4. Adding or Adjusting a Custom Manager

When tracking a new tool or changing version formats:

1. Edit [renovate.yml](file:///renovate.yml) under `customManagers:`.
2. Ensure named capture groups `(?<depName>...)` and `(?<currentValue>...)` are correctly defined.
3. Specify `datasourceTemplate` (e.g., `github-releases`, `github-tags`, `crate`, `pypi`, `npm`, `go`, `rubygems`).
4. Run `bash .agents/skills/renovate-ops/scripts/renovate-sync.sh` to confirm:
   * The regex matches existing lines in target files.
   * `renovate.json` is updated and syntax is valid.

## Troubleshooting

* **Renovate Not Creating PRs for a Target**:
  * Run `renovate-sync.sh` to verify that the regex matches the target file's current version format.
  * Check if the datasource or depName has changed upstream (e.g., tag format prefix `v` mismatch: use `extractVersionTemplate: "^v(?<version>.*)$"`).
* **`renovate.json` Out-of-Sync in CI**:
  * Always commit both `renovate.yml` and `renovate.json`.
  * Verify diff with `git diff renovate.json`.
